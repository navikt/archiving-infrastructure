Kjernen for innsending

innsending-api

Backend-tjenesten lagrer utkast til søknader og vedlegg, genererer og slår sammen PDF-filer, sender innsendinger til arkivering, behandler tilbakemeldinger fra arkivet og rydder opp i midlertidige data.

Type
Kjernebackend
Runtime
Kotlin og Spring Boot
Metadata
PostgreSQL
Filer
Google Cloud Storage

Nesten alle digitale brukerreiser bruker innsending-api til å lagre midlertidig tilstand for innsendinger og filer. soknadsarkiverer og Joark står for den endelige arkiveringen.

Oppgaver

  • Oppretter, leser, oppdaterer og sletter søknader og vedleggsmetadata.
  • Lagrer opplastede filer, skanner dem med ClamAV og genererer og slår sammen PDF-filer via Gotenberg.
  • Støtter varianter for FyllUt, SendInn, ettersending og innsending uten innlogging.
  • Kaller soknadsmottaker når brukeren sender inn, og leverer senere filinnholdet til soknadsarkiverer.
  • Leser tilbakemeldinger fra arkivet, publiserer varsler til brukeren og kjører jobber for opprydding og arkivkontroll.

Livssyklus for data

innsending-api lagrer metadata om søknader, vedlegg, hendelser og konfigurasjon i PostgreSQL. Filinnhold lagres i Google Cloud Storage. Planlagte jobber fjerner gamle utkast og innsendt materiale etter arkivering eller utløp. Joark er langtidsarkivet.

Avgrensning

Tjenesten viser ikke grensesnitt for brukere og oppretter ikke den endelige journalposten i Joark. Den lagrer innsendingen mens soknadsarkiverer behandler den asynkront.

Tekniske detaljer

  • Kotlin, Spring Boot, Java
  • Maven-moduler for API, tjeneste og eksterne klienter
  • PostgreSQL og Flyway
  • Google Cloud Storage
  • REST og Kafka
  • TokenX og Azure AD
  • Autoskalering i NAIS på GCP
