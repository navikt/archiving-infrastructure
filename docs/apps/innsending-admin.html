Drift av innsendinger

innsending-admin

Et internt webgrensesnitt for å undersøke og håndtere innsendinger uten direkte tilgang til databaser eller fillagring.

Type
Frontend for ansatte
Brukere
Drift og brukerstøtte i Nav
Runtime
Next.js og Node.js
Innlogging
Azure AD

Admin-applikasjonen gir innloggede Nav-ansatte tilgang til utvalgte endpoints for drift. innsending-api lagrer tilstanden og utfører handlingene.

Oppgaver

  • Slår opp om en innsending er arkivert.
  • Starter arkiveringsprosessen på nytt hvis den har stoppet, og lenker til logger.
  • Sjekker om et bestemt vedlegg fortsatt er tilgjengelig.
  • Starter navngitte vedlikeholdsjobber.
  • Leser og oppdaterer utvalgte konfigurasjonsverdier.

Rolle i flyten

Nav-ansatte bruker den uavhengig av innsendingsflyten brukeren går gjennom. API-rutene i Next.js på serversiden utveksler ansatt- eller maskintokener og videresender hver handling til innsending-api.

Avgrensning

Den har ingen skjemalogikk for brukere og leser ikke direkte fra lagring. Den holder ikke tilstanden til innsendinger og utfører ikke selve arkiveringen.

Tekniske detaljer

  • Next.js Pages Router
  • TypeScript og Navs designsystem
  • Axios og proxy-ruter på serversiden
  • Azure AD sidecar-innlogging
  • OBO-tokener for ansatthandlinger
  • Maskin-til-maskin-token for filkontroller
  • NAIS på port 3000

Integrasjoner

  • innsending-apiStatus, omstart, jobber, konfigurasjon og filkontroller
  • soknadsarkivererDeploymenten har tilgang, men de viktigste handlingene i grensesnittet går via innsending-api
