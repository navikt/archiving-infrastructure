innsending-admin

An internal web interface for investigating and operating submissions without direct access to databases or file storage.

Type
Employee frontend
Users
NAV operations and support
Runtime
Next.js and Node.js
Login
Azure AD

The admin application puts a narrow, authenticated UI in front of operational endpoints. innsending-api remains the owner of state and actions.

What it does

  • Looks up whether a submission has been archived.
  • Triggers a rerun for a stuck archive process and links operators to logs.
  • Checks whether a specific attachment is still available.
  • Starts named maintenance jobs.
  • Reads and updates selected configuration values.

Role in the flow

It sits beside the normal citizen flow. Server-side Next.js API routes exchange employee or machine tokens and proxy each action to innsending-api.

What it does not do

It has no citizen-facing form logic and does not read storage directly. It is not the submission state machine or archive worker.

Technical details

  • Next.js 14 Pages Router
  • TypeScript and NAV design system
  • Axios and server-side proxy routes
  • Azure AD sidecar login
  • OBO tokens for employee actions
  • Machine-to-machine token for file checks
  • NAIS on port 3000

Connections

  • innsending-apiStatus, rerun, jobs, configuration, and file checks
