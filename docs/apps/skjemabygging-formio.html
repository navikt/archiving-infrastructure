Bygger og FyllUt

Bygger definerer skjemaet. FyllUt viser det og lar brukeren fylle ut og sende inn nye søknader, også med vedlegg. Når begge applikasjonene ligger i ett monorepo, kan de dele skjemamodeller og komponenter, men de har ulike målgrupper, autentiseringsløsninger og release-prosesser.

Oppgaver

  • Bygger lar Nav-ansatte opprette, redigere, migrere, oversette, forhåndsvise og publisere form.io-skjemadefinisjoner.
  • FyllUt viser publiserte skjemaer for brukere, laster opp vedlegg via innsending-api og lar brukeren sende inn digitalt uten å forlate FyllUt.
  • FyllUt støtter også bruk uten innlogging og innsending på papir.
  • Delte pakker inneholder felles domenemodeller, backend-verktøy og frontend-komponenter.
  • Bygger-backend publiserer valgt skjemainnhold til skjemautfylling-formio via GitHub API.

Rolle i flyten

Bygger leser og skriver skjemadata i forms-api. Når skjemaet publiseres, blir innholdet klart for deployment i skjemautfylling-formio. FyllUt viser senere dette innholdet og bruker innsending-api til å lagre søknaden, lage PDF-en, laste opp vedlegg og sende inn søknaden. Bygger og FyllUt bruker skjemabygging-proxy når de trenger en førsteside til papirinnsending. En utdatert overføring til SendInn finnes fortsatt for brukere som har et gammelt utkast med vedlegg som tidligere ble lastet opp der.

Avgrensning

Applikasjonen lagrer ikke søknader permanent og arkiverer ikke dokumenter i Joark. skjemautfylling-formio pakker publisert skjemainnhold for produksjon sammen med FyllUt-koden til deployment.

Tekniske detaljer

  • TypeScript og React 18
  • Express-backender
  • pnpm-workspaces
  • Vitest og Cypress
  • Azure AD for Bygger
  • ID-porten og TokenX for brukerflytene
