Test support

arkiv-mock

A configurable stand-in for Joark, SAF, and innsending-api file retrieval in end-to-end and load tests.

Type
Test double
Environments
Local, CI, and load tests
Runtime
Kotlin and Spring Boot
Production
Never used

The mock makes archive behavior controllable. Tests can make one submission succeed, fail with a chosen response, return malformed data, or pause long enough to exercise timeouts and retries.

What it simulates

  • Joark's create-journal-post REST endpoint.
  • SAF's GraphQL journal-post lookup.
  • innsending-api's submitted-file endpoint with canned PDF files.
  • A control API for response codes, malformed bodies, and delays per submission key.
  • Kafka observations that let system tests assert received entities and call counts.

Role in testing

archiving-infrastructure routes soknadsarkiverer and parts of innsending-api to arkiv-mock. This keeps the test chain local while preserving the external protocols that production uses.

What it does not do

It is not a development version of Joark and must not appear in production. Its stored behavior and fixtures exist to make tests deterministic.

Technical details

  • Kotlin, Spring Boot, Java 21
  • REST and GraphQL endpoints
  • Kafka test observations
  • Configurable fault injection
  • PDF fixtures in several sizes
  • Docker image for local orchestration

Connections

  • soknadsarkivererJoark, SAF, and file test endpoints
  • innsending-apiSAF and Joark test behavior
