forms-api

The persistent backend for form definitions, translations, recipient addresses, publication records, and static PDFs.

Type
Backend service
Primary client
Bygger
Runtime
Kotlin and Spring Boot
Storage
PostgreSQL

forms-api is the editable source of form data. It supports form-building work and the newer publication model, while the production FyllUt image still receives its published content through GitHub.

What it does

  • Creates and updates form definitions and form translations.
  • Stores global translations, recipient and archive addresses, and static PDFs.
  • Tracks publications so one render can refer to a consistent form revision and translation set.
  • Exposes read APIs and protects write operations with Entra ID groups.

Role in the flow

Bygger uses forms-api throughout authoring. Non-production FyllUt can also load forms directly from it for staging. In production, publishing still copies selected content into skjemautfylling-formio before FyllUt serves it.

What it does not do

It does not render forms, publish Git commits, accept citizen submissions, or archive documents.

Technical details

  • Kotlin, Spring Boot 4, Java 21
  • PostgreSQL with Flyway
  • REST API and Swagger UI
  • NAIS on GCP
  • Prometheus through Actuator
  • Entra ID group authorization for writes

Connections

  • ByggerMain read and write client
  • FyllUt stagingOptional direct reads outside production
  • Published contentRelated data, copied by Bygger rather than forms-api itself
