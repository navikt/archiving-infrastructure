soknadsarkiverer

Henter innsendte metadata og filer, hindrer doble journalposter, arkiverer i Joark og sender svaret tilbake.

Type
Kafka-konsument
Arkivmål
Joark
Sjekk av duplikater
SAF GraphQL
Runtime
Kotlin og Spring Boot

soknadsarkiverer bruker innsendte metadata og filreferanser til å opprette en permanent journalpost. Den følger med på behandlingstilstanden og prøver mislykkede arkivkall på nytt, uten å holde brukerens opprinnelige forespørsel åpen.

Oppgaver

  • Konsumerer meldinger om innsending med og uten innlogging fra Kafka.
  • Følger behandlingstilstandene received, started, archived, finished og failure.
  • Henter innholdet i de refererte filene fra innsending-api.
  • Spør SAF med ekstern referanse for å finne ut om søknaden allerede er arkivert.
  • Oppretter en journalpost og dokumenter via Joark API.
  • Publiserer tilbakemelding om arkivering, behandlingshendelser og metrikker.

Feilhåndtering

soknadsarkiverer prøver på nytt ved forbigående feil, med stadig lengre pauser. Når den har brukt opp alle forsøkene, setter den oppgaven til failure og publiserer et negativt svar. Den håndterer allerede arkiverte innsendinger og slettede filer separat, fordi det ikke hjelper å prøve dem på nytt.

Avgrensning

Den mottar ikke opplastinger fra nettleseren og har ikke ansvar for midlertidig fillagring. Den starter når soknadsmottaker har godkjent og publisert metadataene.

Tekniske detaljer

  • Kotlin, Spring Boot, Java
  • Kotlin-coroutiner
  • Konsumering og publisering i Kafka
  • Generert innsending-api-klient
  • GraphQL-klient for SAF
  • REST-klient for Joark
  • Azure AD-klientlegitimasjon
  • Admin-API beskyttet med JWT
