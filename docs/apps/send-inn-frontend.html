SendInn

The logged-in web client where citizens resume applications, upload documents, and complete a digital submission.

Repository
send-inn-frontend
Type
Citizen frontend
Runtime

Backend
innsending-api

SendInn is the final user-facing step for digital submissions that include documents. It keeps backend credentials and token exchange on the server side while streaming uploads to innsending-api.

What it does

  • Opens an existing submission by ID and displays its state.
  • Lets the citizen upload, replace, and remove documents.
  • Completes normal applications, additional documentation, and document-only submission routes.
  • Fetches form metadata from FyllUt when it needs to display form context.

Role in the flow

FyllUt and fyllut-ettersending redirect users here when files must be uploaded. SendInn's Next.js API routes proxy requests and streams to innsending-api with a TokenX bearer token. innsending-api owns the resulting application state and files.

What it does not do

It does not define forms, own persistent application data, generate the original form PDF, publish Kafka messages, or archive documents.

Technical details

  • Next.js 16 and React 19
  • Pages Router
  • Standalone Node server
  • ID-porten login and TokenX exchange
  • Streaming backend proxy
  • Sentry error reporting
  • NAIS deployment variants
