soknadarkiv-schema

Et versjonert Maven-artefakt med Avro-poster fra arkiveringsflyten. Det brukes nå hovedsakelig til historisk behandling og kompatibilitet for metrikker.

Type
Skjemabibliotek

Ingen i seg selv

Den aktive innsendingmeldingen er JSON. Avro-typene støtter eldre hendelser, metrikker og kompatibilitet for replay. Repo-navnet og eldre README-filer kan gi inntrykk av at dette fortsatt definerer hovedkontrakten for innsending.

Innhold

  • Det historiske skjemaet for søknadsarkiv.
  • Poster for behandling og enumen for hendelsene received, started, archived, finished og failure.
  • Metrikkposter og delte Avro-elementer.
  • Maven-byggkonfigurasjon som genererer typer og publiserer pakken.

Rolle i flyten

soknadsmottaker og soknadsarkiverer er avhengige av artefaktet for delte historiske typer. Standardflyten for innsending med versjon 3 bruker ren JSON i InnsendingTopicMsg og trenger ikke Schema Registry for hovedinnholdet.

Konsekvens for planlegging

Før du redigerer et skjema, må du finne ut om det berørte topicet bruker aktiv JSON, aktiv Avro eller er bevart for migrering og replay. Ikke trekk slutninger om den aktive kontrakten ut fra repo-navnet alene.

Tekniske detaljer

  • .avsc-skjemafiler
  • Genererte typer som er kompatible med Java og Kotlin
  • Publisering av Maven-pakken
  • Semantisk kompatibilitet er viktig for Kafka-historikken

Integrasjoner

  • soknadsmottakerAvhengighet på produsentsiden
  • soknadsarkivererAvhengighet for konsument og hendelser
  • archiving-infrastructureBeholder Schema Registry for eldre replay-scenarioer
