Archiving intake

soknadsmottaker

The small but important boundary between synchronous submission over REST and asynchronous archive processing over Kafka.

Type
REST intake service
Caller
innsending-api
Output
Kafka JSON
Runtime
Kotlin and Spring Boot

soknadsmottaker accepts the submitted metadata, maps it to the Kafka message, and publishes it. It does not fetch files or talk to Joark.

What it does

  • Receives logged-in and no-login application metadata through separate REST endpoints.
  • Maps requests to InnsendingTopicMsg and masks national identity numbers in ordinary logs.
  • Publishes submission JSON to the matching Kafka topic.
  • Also exposes notification endpoints that publish message, task, draft, and done events.
  • Publishes submission metrics.

Role in the flow

innsending-api calls it after the user commits a submission. A successful publish lets the user-facing request finish while soknadsarkiverer processes the archive work independently.

What it does not do

It does not retain uploaded files, enrich metadata, perform retries against Joark, or own final archive status.

Technical details

  • Kotlin and Spring Boot 4
  • Java 21 and Maven
  • OpenAPI REST contract
  • Kafka producer
  • Separate logged-in and no-login topics
  • Secure logging for sensitive identifiers
  • NAIS deployment

Connections

  • innsending-apiREST caller with submitted metadata
  • soknadsarkivererConsumes the JSON message
  • soknadarkiv-schemaLegacy event and metrics records, not the primary JSON payload
