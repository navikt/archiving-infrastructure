skjemabygging-proxy

A narrow proxy that lets the form-building applications call Foerstesidegenerator across the GCP-to-FSS boundary.

Type
Backend proxy
Primary clients
Bygger and FyllUt
Runtime
Node.js and Express
Deployment
NAIS in FSS

The proxy keeps FSS connectivity and legacy service credentials out of the GCP applications. Its public responsibility is limited to authenticating callers and forwarding cover page requests.

What it does

  • Exposes the /foersteside endpoint to Bygger and FyllUt.
  • Validates incoming Azure AD access tokens through NAIS token introspection.
  • Obtains and caches a short-lived STS token using a service user.
  • Forwards requests to Foerstesidegenerator with the STS bearer token, API key, and consumer ID.
  • Exposes internal health and Prometheus endpoints and adds correlation IDs to error responses.

Role in the flow

When Bygger or FyllUt needs a cover page for paper delivery, its backend requests one through this proxy. The proxy crosses into FSS, translates the authentication context, and returns the generated PDF response. It is outside the digital submission and archiving path.

What it does not do

It does not build or render forms, store application data, generate the cover page itself, submit applications, or archive documents.

Technical details

  • Node.js 24 and Express 5
  • HTTP proxy middleware
  • Azure AD token introspection
  • STS client credentials
  • Prometheus metrics and structured logs
  • NAIS deployment in FSS
