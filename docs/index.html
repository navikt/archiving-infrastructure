The short version

What the team delivers

The system covers two connected domains. Form tooling defines what users fill in. Submission and archiving services move the result into Nav's archive.

Build and publish forms

Internal form builders create definitions and translations in Bygger. Production FyllUt bundles published content from the skjemautfylling-formio repository.

See Bygger and FyllUt

Guide users through submission

FyllUt renders new forms and handles their attachments through innsending-api. SendInn handles additional documentation and the remaining legacy drafts from the old handoff.

Compare user paths

Store and archive documents

innsending-api stores work in progress. After submission, Kafka separates intake from the archiver, which fetches files and writes a journal post to Joark.

A citizen's submission

Four stages, end to end

The form definition takes a separate publishing path. Once a user starts filling it in, the live submission path looks like this.

Fill in and attach

FyllUt renders a published form and uploads attachments for the new application directly through innsending-api.

Store and submit

innsending-api holds application metadata and files while the user works, then sends metadata to soknadsmottaker.

Queue and enrich

soknadsmottaker publishes JSON to Kafka. soknadsarkiverer consumes it and fetches the file bytes from innsending-api.

Archive and report

soknadsarkiverer checks SAF for duplicates, creates the journal post in Joark, and reports the outcome back through Kafka.
