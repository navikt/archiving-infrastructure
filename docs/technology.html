Recurring patterns

NAIS and GCP

Deployable applications run on NAIS. Java services use Java 21. innsending-api also provisions Cloud SQL and Google Cloud Storage.

Identity by audience

Citizen calls use ID-porten and TokenX. Employee tools use Azure AD or Entra ID. Service calls use Azure AD client credentials or OBO tokens.

REST before Kafka

User-facing clients call synchronous REST APIs. Kafka begins after submission, where asynchronous processing and retry behavior are useful.

OpenAPI at service edges

Several services generate API interfaces or clients from OpenAPI. Contract changes should account for both the producer and generated consumers.

Temporary versus permanent data

innsending-api owns temporary application and file storage. Joark owns the permanent journal post. SAF provides archive lookup.

End-to-end tests

archiving-infrastructure tests the assembled archive chain. arkiv-mock makes success, failure, delay, and duplicate scenarios reproducible.

Change planning checklist

Before changing a shared flow, identify the source of truth, generated clients, asynchronous consumers, and rollout order. Pay particular attention to form publication versus runtime content, the REST-to-Kafka handoff, JSON versus legacy Avro records, and how archive feedback changes cleanup or user notifications.
